# SPORTOTEKA Tracker V154 — устойчивое восстановление GPS

Исправления по журналу команды 40 от 18.08.2026:

- MySQL `1213 Deadlock` при финализации offline recovery автоматически
  повторяется до пяти раз с блокировкой строки recovery job.
- Один recovery job больше не запускается параллельно из нескольких экранов
  Flutter.
- Если GPS-точки уже загружены в server staging, а упала только финализация,
  приложение повторяет finalize без повторного скачивания большого BLE-файла.
- Таймаут серверной финализации увеличен до 5 минут для файлов на десятки тысяч
  точек.
- Обрыв BLE при чтении файла больше не блокирует очередь остальных трекеров на
  15 минут: попытка завершается после обрыва либо 35 секунд без новых данных и
  автоматически повторяется после reconnect.
- Reconnect разрешён только по точному UUID/MAC или стабильному имени
  `$ATP-Cxxxx`. Подключение к чужому ATP/GPS или `Redmi Watch` запрещено.
- Recovery jobs со статусом `waiting`/`pending` больше не блокируют новый Team
  Live. Во время нового матча они ставятся на паузу и продолжаются после Stop.
- Если в момент нажатия «Старт» физически читается старый BLE-файл, V154
  автоматически ставит передачу на паузу, закрывает остаточный поток 44/45,
  переподключает тот же ATP и запускает новый Live. Recovery продолжится после
  Stop.

Сначала заменить серверный `php/tracker_offline_recovery.php`, затем файлы
Flutter из папки `tracker/services/` и пересобрать приложение.

После обновления открыть экран «Трекеры / Устройства», оставить нужные ATP
включёнными рядом с планшетом и не запускать новый Team Live до появления
`team_offline_recovery_done`.
