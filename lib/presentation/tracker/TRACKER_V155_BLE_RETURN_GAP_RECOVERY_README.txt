SPORTOTEKA TRACKER V155 — BLE RETURN + GAP RECOVERY
===================================================

Что исправлено
--------------
1. Во время Team Live GPS-команды больше не запускают собственные долгие
   connect/scan. Потерянный канал восстанавливает один общий watchdog.
2. Watchdog выполняет только прямой reconnect по точному UUID/MAC датчика.
   Общий BLE scan во время Live запрещён, чтобы не обрывать остальные GATT.
3. Одновременно может выполняться только одно восстановление GATT. Пока оно
   идёт, новые GPS-команды не копятся в очереди.
4. Лишние GPS-каналы, не входящие в текущий состав Live, отключаются перед
   стартом. Серверные назначения игроков при этом остаются сохранёнными.
5. Несколько открытых workspace присоединяются к одному GPS/Polar scan вместо
   параллельных stopScan/startScan.
6. После возврата датчика Live продолжается с текущей точки. Интервал от
   последней GPS-точки перед потерей до первой валидной точки после возврата
   записывается как gap. Даже короткий пропуск более 5 секунд фиксируется.
7. После Stop готовый файл из памяти ATP дочитывается, сервер вставляет только
   точки внутри gap, удаляет дубли по time_ms и пересчитывает аналитику.
8. В Remote Debug добавлены события team_ble_gap_open и
   team_ble_gap_closed, по которым видно границы восстановления.

Ожидаемое поведение
-------------------
- Датчик ушёл далеко: карточка показывает проблему, но общий Live не
  останавливается и работающие игроки продолжают получать GPS.
- Датчик снова рядом: один прямой reconnect возвращает TX/RX без общего scan.
- Первая валидная GPS-точка закрывает gap, новые точки снова идут в Live.
- После Stop пропущенный участок появляется в итоговой аналитике из памяти ATP.

Контрольные строки Remote Debug
-------------------------------
- "один прямой reconnect по точному UUID, без scan"
- "канал восстановлен · Live GPS продолжен"
- "BLE GAP OPEN"
- "BLE GAP CLOSED"
- "Офлайн GPS восстановлен"

Важно
-----
Текущий recording-файл ATP нельзя скачивать в середине матча. Поэтому при
возврате датчика сразу продолжается Live, а сам пропущенный участок безопасно
дочитывается после Stop, когда запись становится finished.
