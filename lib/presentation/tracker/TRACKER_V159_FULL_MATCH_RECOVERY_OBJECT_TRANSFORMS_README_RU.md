# Sportoteka Tracker V159 — полный матч из ATP и трансформации разбора

## Что исправлено

- При `Stop` для каждого игрока создаётся recovery job на **всё окно матча**, а
  не только на отдельные BLE/network-разрывы.
- Уже принятые Live-точки не дублируются: сервер сверяет время точек и добавляет
  только недостающие данные из полного файла ATP.
- Выгрузка стартует сразу после `Stop` и повторяется каждые 15 секунд, пока файл
  не станет `finished` и трекер остаётся доступен.
- Закрытие workspace больше не уничтожает общий BLE-pool, пока реально идёт
  чтение/загрузка файла.
- Новая Live-сессия не блокируется recovery: `Start` ставит текущий file-transfer
  на паузу, переподключает тот же ATP и продолжает выгрузку после следующего
  `Stop`.

## Разбор и аналитика

В `tg_analytics_overlay.dart` выбранные элементы получили:

- четыре активные угловые ручки пропорционального масштаба;
- отдельную ручку свободного вращения;
- перемещение за тело объекта;
- масштаб и поворот кнопками для всех поддерживаемых объектов, а не только
  `TgStamp`;
- сохранение каждой трансформации через общий mutation/cache/server payload;
- полноценный поворот текста и заметок;
- Undo / Redo для перемещения, масштаба и вращения.

Один overlay используется и в полноэкранной аналитике, и в режиме «Разбор»,
поэтому поведение и сохранение одинаковые в обоих местах.

## Установка

1. Заменить Flutter-папку `lib/presentation/tracker/` содержимым `tracker/`.
2. Заменить
   `lib/presentation/training_graphics/tg_analytics_overlay.dart` файлом из
   `training_graphics/`.
3. Оставить установленным актуальный серверный
   `api/tracker/tracker_offline_recovery.php` из V154/V155 и пересобрать Flutter.

Миграций БД в V159 нет.

## Важно для аппаратного файла ATP

Файл со статусом `recording` прошивка ATP читать не разрешает. Recovery job уже
сохранён и не теряется: после того как датчик закроет запись и снова будет
доступен по BLE, приложение автоматически увидит `finished`, скачает полный файл
и пересчитает финальную сессию. Контрольная строка Remote Debug:
`team_offline_recovery_done`.
