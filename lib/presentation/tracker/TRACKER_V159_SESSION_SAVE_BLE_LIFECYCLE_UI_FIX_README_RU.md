# TRACKER V159 — сохранение Team Live, BLE lifecycle, overflow

Дата: 20.08.2026

## Что показали логи и дамп БД

1. Первая командная сессия 20.08 сохранена на сервере нормально: `tracker_live_sessions` / `tracker_sessions` 792–795 имеют ненулевой метраж (примерно 1.4–1.8 км на игрока).
2. Следующий Team Live не смог создать серверные каналы, потому что `$ATP-C1580 / CC:04:08:AC:00:02` в `tracker_devices` оставался назначен `player_id=79`, а локальный состав пытался запустить его для другого игрока. Сервер вернул: `уже назначен другому игроку`.
3. Координатор ошибочно трактовал любое исключение старта сервера как отсутствие интернета. Поэтому Live продолжился только локально и Remote Debug показывал сообщение `Интернет недоступен`, хотя реальная причина была в конфликте назначения.
4. Во втором локальном Live метраж реально считался в приложении (Remote Debug показывал примерно 4.1–5.3 км по каналам), но серверных live-session строк не было. При поздней регистрации локального Live старый код мог сразу выполнить Stop до отправки накопленного total — отсюда риск финальной сессии с `0 м` до offline-recovery.
5. `Bad state: Cannot add new events after calling close` идёт из `ActionTrackerBleService._emitDevices`: scan callback продолжал приходить после `dispose()`, когда broadcast controller уже закрыт.
6. `RenderFlex overflowed by 8.3 pixels on the right` — три `_MapModeButton` в правом detail panel имели суммарную intrinsic-ширину больше доступных `236.8 px`.
7. Android `GATT 133` в конце лога относится к попыткам reconnect уже давно молчащих/отключённых GPS. В pool уже есть последовательная GATT-очередь и backoff; основной crash/потерю server-session в этом патче устраняют пункты выше.

## Что изменено

### 1. Серверная привязка GPS синхронизируется перед Team Live

В `TrackerLiveApi` добавлен `syncTrackerBinding(...)` с `replace_existing=1`.

`TeamTrackerLiveCoordinator._startServerSessions()` перед общей транзакцией Team Live последовательно подтверждает на сервере все текущие назначения. Старое назначение одного GPS больше не должно валить всю команду.

### 2. Локальный Live больше не должен финализироваться как 0 м

При автоматическом переводе local-only Live на сервер после создания server live-session отправляется один `LOCAL_OFFLINE_SUMMARY_CHECKPOINT` с накопленными:

- `total_distance_m`;
- `max_speed_kmh`;
- `avg_speed_kmh`;
- последней валидной координатой/временем.

`distance_delta_m=0`, чтобы последнюю дельту не посчитать дважды.

Только после успешного checkpoint координатор снимает `_localOnly`. Поэтому Stop уже видит на сервере накопленный метраж, а полная ATP offline-recovery всё равно остаётся источником истины для маршрута.

### 3. Исправлена диагностика local-only

Сообщения больше не утверждают, что обязательно пропал интернет. Теперь отображается, что серверный Live пока не создан/не принят, а GPS и метрики продолжаются локально.

### 4. Исправлен BLE callback after dispose

В `ActionTrackerBleService` добавлен lifecycle-флаг `_disposed` и защита всех поздних `scan`, `connectionState`, `notify`, `_emitDevices`, `_log` callbacks. `dispose()` ставит флаг до первого `await`.

Это закрывает стек:

`_BroadcastStreamController.add -> ActionTrackerBleService._emitDevices -> scanResults.listen`.

### 5. Исправлен RenderFlex 236.8 px

Только узкая строка `График / События / Сессия` получила три равных `Expanded + FittedBox(BoxFit.scaleDown)`. Сам `_MapModeButton` глобально не менялся, поэтому горизонтальные scroll-toolbar не ломаются.

## Как проверить

1. Собрать приложение с этим `tracker`.
2. Подключить текущую сохранённую команду и запустить Team Live.
3. В Remote Debug не должно быть ошибки `$ATP-C1580 уже назначен другому игроку`; серверные Live ID должны быть обычными, не `700040...`.
4. Сделать 2–3 минуты теста, Stop, проверить ненулевой метраж в аналитике.
5. Отдельно выключить интернет во время короткого теста, пройти с GPS, вернуть интернет и Stop. После promotion метраж должен появиться на сервере сразу, ещё до полной выгрузки ATP-файла.
6. Открыть/закрыть экран во время/после BLE scan — `Cannot add new events after calling close` больше не должен появляться.
7. Открыть аналитику в ширине, где detail panel около 236–240 px — жёлто-чёрного overflow справа быть не должно.

## Как попробовать вернуть уже не попавшую на сервер последнюю запись

Не стирать память трекеров. После корректной привязки подключить нужный GPS и запросить список GPS-записей. В workspace уже есть автовыгрузка последней finished-записи: она читает файл ATP, сохраняет его через `saveGpsSession()` и запускает обработку сессии. Это отдельный путь восстановления уже прошедшего локального Live, который не успел получить server live-session.
