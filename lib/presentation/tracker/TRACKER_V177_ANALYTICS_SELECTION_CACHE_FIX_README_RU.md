# Tracker V177 — сохранение выбранной сессии/игроков + устойчивость аналитики

Дата: 2026-08-20

## Что исправлено

1. Выбранная командная тренировка больше не схлопывается до одного игрока после перехода в другой раздел Tracker и возврата в Аналитику.
   - сохраняются все `session_ids` выбранной тренировки;
   - сохраняются выбранные `player_ids`;
   - сохраняются строки сессии по игрокам (`sessionRows`), дата и тип тренировок;
   - состояние хранится в `TrackerMatchWorkspaceScreen`, потому что desktop специально удаляет скрытые разделы из дерева.

2. При кратком `SocketException: Connection refused` аналитика больше не заменяет успешные данные пустыми.
   - `TrackerProApi` хранит last-known-good ответы аналитических GET;
   - свежий кэш до 45 секунд используется без повторного сетевого запроса;
   - если сеть упала позже, используется последний успешный ответ;
   - ручной Refresh и `dataRevision` после recovery очищают аналитический API-кэш.

3. Добавлен memory-cache готового `_AnalyticsBundle`.
   - при возврате в Аналитику тот же набор session/player ids показывается сразу;
   - до 45 секунд повторная загрузка вообще не требуется;
   - после TTL старый bundle остаётся на экране, пока идёт тихое обновление.

4. Даже если список сессий от API временно пустой, bundle дополняется сохранёнными technical rows выбранной тренировки. Это не даёт командной сессии превратиться в один `representative_session`.

5. Добавлена адаптация правого блока «Радар выбранной сессии» для небольшой высоты окна, чтобы фиксированная нижняя строка не вызывала `RenderFlex overflow`.

## Что не менялось

- V165 Auto Recovery / Live Priority;
- V176 запрет фонового BLE scan/reload;
- серверная схема и PHP API;
- GPS/Polar расчёты;
- полный набор разделов аналитики и выбор сессии.
