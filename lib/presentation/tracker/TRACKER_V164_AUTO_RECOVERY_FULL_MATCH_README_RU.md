# SPORTOTEKA Tracker V164 — автоматическая послематчевая выгрузка ATP

## Зачем этот патч

По дампу БД и Remote Debug от 20.08.2026 проблема оказалась не в самой записи GPS:
после Stop сервер создаёт `tracker_offline_recovery_jobs`, но часть задач оставалась
`waiting/pending`. При этом Android после Stop многократно отдавал GATT 133, а старый
recovery пропускал GPS, если его BLE-канал уже считался отключённым.

Для последнего теста команды 40 jobs 23–26 уже существуют. Две задачи успели перейти
в `waiting`, две оставались `pending`. Поэтому создавать отдельную тренировку для
этой записи не нужно: надо дочитать ATP и дополнить уже созданные `final_session`.

## Что изменено в V164

### 1. Автовыгрузка действительно продолжается после Stop

После Stop для каждого GPS с pending recovery:

1. серверная задача сохраняется;
2. приложение проверяет её сразу;
3. если ATP недоступен — сохраняет pending-состояние;
4. повторяет проверку каждые 15 секунд;
5. если GATT 133 удалил старый connection — открывает тот же сохранённый UUID/MAC заново;
6. запрашивает список файлов ATP;
7. если нужный файл ещё `recording`, ждёт его перехода в `finished`;
8. скачивает finished-файл;
9. оставляет только GPS-точки окна конкретного матча;
10. загружает их в существующую `final_session` через offline recovery;
11. сервер добавляет недостающие точки и пересчитывает финальную сессию.

Никаких ручных кнопок для нормального сценария после Stop нажимать не требуется.

### 2. Recovery не умирает при уходе с экрана

Раньше Timer recovery прекращался при `dispose()` workspace, если файл ещё только
ждал `finished` или BLE уже отвалился. Теперь coordinator удерживает shared BLE-pool
фоновым lease до тех пор, пока сервер реально возвращает pending/waiting jobs.

То есть после Stop можно перейти в другой раздел приложения. Пока само приложение
остаётся запущенным, recovery продолжает попытки в фоне.

### 3. Pending jobs подхватываются после повторного открытия приложения/экрана

При открытии Tracker workspace сохранённая команда сначала восстанавливается, затем
приложение автоматически спрашивает сервер о старых pending jobs для всех сохранённых
GPS-привязок. Даже если GPS не найден первым scan, сохраняется его UUID/MAC и recovery
продолжает прямые попытки каждые 15 секунд.

### 4. Защита от reconnect storm

Один recovery-pass может занимать больше 15 секунд при Android GATT 133. Новый Timer
не запускает второй параллельный проход, пока предыдущий не завершился. Это не даёт
копить connect-команды в BLE-очереди и дополнительно раскачивать Android GATT.

### 5. Исправлено определение ATP-файла при сдвиге часов

Сначала используется прежнее прямое UTC-сопоставление. Только если подходящего файла
вообще нет, V164 пробует timezone-like сдвиги с шагом 30 минут в диапазоне ±14 часов
и выбирает максимальное пересечение с окном матча. Это нужно для партий ATP, которые
могут отдавать внутренние date/time не в том часовом представлении, что epoch server job.

Прямое совпадение всегда имеет приоритет — уже корректные ATP не меняются.

### 6. Карта и аналитика обновляются после recovery автоматически

После успешного `finalizeOfflineRecovery` workspace увеличивает ревизию GPS-данных:

- сбрасывается cache аналитического bundle;
- перечитывается серверная сессия;
- открытая карта получает полный маршрут без ручной смены вкладки;
- Live/summary перечитывает серверное состояние.

Это исправляет ситуацию, когда сервер уже дополнил ту же `final_session`, а экран
продолжал показывать старый неполный Future/cache.

### 7. Старый single-BLE автоимпорт не дублирует Team recovery

Старый путь `saveGpsSession()` может создавать отдельную GPS-сессию. Пока Team Live
или post-Stop recovery активен, его автоматический импорт заблокирован. Для командного
матча источником истины является `tracker_offline_recovery.php`, который дополняет
существующую финальную сессию.

## Ручной контроль

Добавлена кнопка **«Восстановить GPS»**:

- в `Устройствах`;
- в `Истории`;
- из действия offline records в аналитике.

Окно показывает по игроку:

- GPS и BLE online/ожидание;
- server recovery job;
- final session;
- найденный ATP file;
- `recording/finished`;
- размер файла;
- применённый clock shift, если он потребовался;
- последнюю причину ожидания.

Кнопка **«Восстановить сейчас»** запускает тот же безопасный recovery вручную. Она
не создаёт вторую тренировку.

## Важное ограничение ATP

Прошивка ATP не позволяет нормально скачать файл, пока он имеет статус `recording`.
Поэтому «автоматически» не всегда означает «в ту же секунду после Stop».

Если после Stop файл ещё `recording`, приложение оставляет job в ожидании и проверяет
его снова. Как только ATP отдаст `finished` и BLE станет доступен, выгрузка продолжится
сама.

До появления `team_offline_recovery_done` **не очищать память ATP**.

## Что смотреть в Remote Debug

Полезные строки:

- `POST-STOP AUTO RECOVERY` — попытка вернуть BLE после Stop;
- `team_offline_recovery_wait` — файл/датчик пока не готов;
- `team_offline_recovery_clock_shift` — применена коррекция часов ATP;
- `OFFLINE DOWNLOAD START` / `OFFLINE DOWNLOAD DONE` — чтение файла;
- `team_offline_recovery_done` — точки восстановлены и final session обновлена.

## Установка

1. Заменить Flutter-папку `lib/presentation/tracker/` содержимым папки `tracker/`
   из архива V164.
2. Оставить на сервере актуальный `api/tracker/tracker_offline_recovery.php`
   из ветки V154/V155/V159.
3. Выполнить `flutter analyze` и собрать приложение.

Миграций БД для V164 нет.

## Как проверить

1. Установить V164.
2. Открыть Tracker с включёнными сохранёнными ATP.
3. Для уже потерянной тренировки **не создавать новую сессию**.
4. Открыть `Устройства → Восстановить GPS` и проверить jobs/ATP file.
5. Если file `finished` — recovery должен начаться сразу.
6. Если file `recording` — оставить ATP рядом; V164 продолжит проверку автоматически.
7. После `team_offline_recovery_done` открыть ту же сессию в аналитике: маршрут должен
   перечитаться уже с восстановленными серверными точками.
8. Новый тест: запустить Team Live на 5–10 минут, Stop, оставить ATP рядом и убедиться,
   что нет необходимости нажимать «Загрузить GPS» вручную.

## Проверка исходников

В среде подготовки архива нет Flutter/Dart SDK, поэтому `flutter analyze`/полную
компиляцию здесь выполнить нельзя. Для изменённых Dart-файлов выполнена статическая
проверка баланса скобок/строк и просмотр diff относительно V159.
